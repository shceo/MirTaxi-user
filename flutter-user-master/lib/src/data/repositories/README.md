# Слой репозиториев

Куда мы идём и почему именно так.

## Что было

Вся работа с сетью и состоянием жила в `lib/src/core/services/functions.dart` —
3581 строка, 95 функций верхнего уровня и десятки глобальных изменяемых
переменных. Экраны читали и писали эти глобалы напрямую, поэтому:

- нельзя проверить экран без реального бэкенда;
- любая правка в одной функции задевала произвольные экраны;
- один и тот же запрос вызывался из разных мест по-разному.

## Куда идём

```
data/
  models/            типизированные модели ответов
  repositories/      единственная точка входа в API по домену
presentation/
  viewmodels/        состояние экрана, ChangeNotifier
  views/             только отрисовка
```

Правило простое: **экран не знает о сети**. Экран обращается к своей
`ViewModel`, `ViewModel` — к репозиторию, репозиторий — к API.

## Как переносим, не ломая приложение

Способом «удушающего фикуса»: репозиторий сначала просто **оборачивает**
существующую функцию из `functions.dart`. Поведение не меняется ни на байт,
но вызывающий код уже обращается к новому адресу. Когда все вызовы одной
функции переехали на репозиторий, её реализация переносится внутрь
репозитория, а из `functions.dart` удаляется.

Так `functions.dart` худеет постепенно, и на каждом шаге приложение остаётся
рабочим. Переписывать god-файл целиком за один заход нельзя — это гарантия
недельного регресса на проекте, где нет ни одного теста.

## Порядок переезда

Экран переезжает на MVVM тогда, когда до него доходит редизайн. Смысла
рефакторить экран, который через час будет переписан, нет.
